# 六轴监测前端

按用户提供的 `stitch_.zip` 复刻银蓝色 SIX-AXIS IMU LAB 仪表台。实时监测页直接复用导出稿的布局、色板、字体、Material Symbols 图标、六面传感器模型和背景坐标网格。保留普通用户的登录、设备与资料管理，并增加三维姿态、实时曲线、原始轴统计和每日历史步数。原来的权限探测、JSON 报文和接口日志不再作为用户页面展示。

## WSL 与后端统一运行

需要 Node.js 22.12+ 或 24+。

    cd /home/root/IoTDA/frontend
    npm ci
    npm run build
    cd ..
    .venv/bin/python run.py

- 统一入口：<http://127.0.0.1:5000/test-ui/>；演示入口：<http://127.0.0.1:5000/test-ui/?demo=1>。
- Flask 从 `frontend/dist/` 提供构建页面和所有静态资源，与 `/api` 共用端口和 Cookie，不需要额外启动 Vite，也无需配置 `API_TARGET`。
- `npm ci` 仅在首次安装或依赖变更时需要，按锁文件安装 WSL/Linux 依赖。不要把 Windows 的 `node_modules` 直接复用于 WSL。
- 日常启动只运行项目根目录的 `.venv/bin/python run.py`。修改前端后执行 `npm --prefix frontend run build`，再刷新浏览器即可。

## 单独开发前端（热更新）

需要前端热更新时，在 WSL 中另开终端；后端仍通过项目根目录的 `run.py` 启动：

    cd /home/root/IoTDA/frontend
    cp .env.example .env.local
    npm run dev

- 正常入口：<http://127.0.0.1:5173/>
- 显式演示入口：<http://127.0.0.1:5173/?demo=1>
- 演示模式也可以从登录页面进入。它只修改当前页面内存，不请求真实接口、不保存到数据库，刷新会恢复演示初始数据。右上角始终标记“演示模式”。
- 演示数据包含一台有数据的设备和一台无数据的备用设备，用于检查数据隔离和空状态。

## 连接真实后端

编辑 .env.local 的 API_TARGET，例如后端同机运行时：

    API_TARGET=http://127.0.0.1:5000

如果后端位于另一台电脑，替换成后端实际局域网地址。修改后重启 Vite。所有业务请求均使用相对 /api 路径、credentials: 'include' 和同源代理；没有在前端存储 token，也不需要云端凭据。

`API_TARGET` 只作用于 Vite 开发代理，通过后端 `5000/test-ui/` 统一访问时不使用它。正常模式连接失败时显示错误，不会自动切换到演示数据。真实账户、设备绑定授权和实物传感器仍需按实际后端环境联调。

## 页面与交互

WebSocket 会自动使用同一后端的 `/api/telemetry/live`。使用 Vite 独立开发时，后端的 `FRONTEND_ORIGIN` 必须与浏览器来源精确一致，例如 `http://127.0.0.1:5173`；统一通过 `5000/test-ui/` 访问时不需要此额外配置。协议见 [WebSocket 与告警](../docs/WebSocket与告警.md)。

| 页面 | 已实现行为 |
| --- | --- |
| 登录/注册 | 字段校验、密码清理、注册后转登录、刷新时恢复 Cookie 会话、连接及鉴权错误反馈 |
| 实时监测 | 切换设备、三维模型拖动/滚轮缩放/方向键旋转/重置、网格显隐、透视/正交投影、放大、实时姿态与标记、加速度/角速度切换 |
| 曲线 | 30/60/120/300 秒窗口、原始数据/滑动平均、1–50 样本滤波窗口、悬停提示、原始窗口统计展开 |
| 历史步数 | 全用户设备合计、7/30 天快捷范围、自定义含首尾日期查询、每日明细展开、缺失记录与零步区分 |
| 我的设备 | 刷新、绑定、重命名、解绑确认、从设备跳到监测、无设备引导 |
| 个人资料 | 修改用户名/邮箱、清空邮箱、旧密码与新密码校验、密码修改成功后重新登录 |
| 账户菜单 | 打开/关闭、个人资料、退出；点击外部或 Escape 关闭菜单 |

真实模式优先连接 WebSocket，姿态和曲线随新样本更新；实时连接失败时使用 HTTP 备用查询，请求完成后才安排下一秒轮询；设备切换、页面离开、隐藏标签页、退出、登录会话失效都会停止旧轮询。账户/设备代次和 AbortController 共同避免旧响应覆盖新数据。受保护接口 401 会清空旧账户信息，登录和修改密码自身的 401 单独作为凭据错误处理。写入不会自动重试。

图表使用北京时间。步数增量显示为“本次步数增量”；历史记录没有冒充当天实时累计，步数目标和远程控制尚未提供；后端新增的告警事件在页面告警列表中展示，保留查询最近 7 天，页面最多显示 50 条。

## 姿态坐标约定

使用 Stitch 提供的 CSS 六面模型外观，通过 Three.js 的四元数与矩阵运算驱动实时姿态，不再需要 WebGL 渲染器。视角拖动、投影与缩放不会改动传感器数值。`lib/sensor-scene.js` 的 `SENSOR_ALIGNMENT` 暂沿用导出稿的显示约定：pitch → X、roll → Y、yaw → Z，旋转顺序 XYZ。跨越 ±180° 使用最短路径插值；无样本时隐藏模型并禁用视角工具；减少动态效果偏好下直接更新。

原接口文档明确说物理坐标映射与旋转顺序尚待确认。接入实物后，需要分别绕三个轴旋转并核对方向；模型外观为设计示意，不代表具体硬件外形已经测量。

## 构建与交付

    npm test
    npm run build

dist/ 为可部署静态产物。当前 Flask 已从此目录提供 `/test-ui/` 页面及资源，并同时提供同源 `/api`；开发代理只在 Vite 开发服务中生效。构建采用相对资源路径；请完整部署 dist/，包含 assets/，不能只替换单个 HTML 文件。`/test-ui` 会重定向到带尾斜杠的 `/test-ui/`。缺少 dist/index.html 时，后端页面入口返回 503 和构建提示。

## Stitch 来源与素材

- 原始导出：项目上级目录的 `stitch_.zip`。
- 解包参考：`design/stitch-source/code.html`、`screen.png`、`DESIGN.md`，保留原件便于后续核对。
- 样式：Tailwind 3 本地构建，主题来自导出稿；扩展状态和移动端规则在 `styles.css`，其他业务页的共享样式在 `workflow.css`。
- 字体：Inter、Space Grotesk、JetBrains Mono 与 Material Symbols Outlined 保存在 `assets/fonts/`，随生产资源一起打包，不依赖运行时访问 Google Fonts 或 Tailwind CDN。
- 图标：监测页使用导出稿的 Material Symbols；原有业务流程继续使用 Phosphor。曲线使用 Apache ECharts；姿态运算使用 Three.js。
- `public/assets/avatar-mountain.png` 保留给个人资料页；此前主题的设计截图和传感器纹理是历史记录，不作为本轮视觉参考。

导出稿仅包含实时监测页；登录、历史、设备与个人资料沿用已有功能并统一为银蓝色。桌面保留双列仪表布局；平板收起次要头部文案；手机使用单列与底部导航，并保留明确的演示模式标识。

静态设计中没有接口依据的同步率、固件版本、AHRS 引擎、100Hz、军事标准、分析员身份等已替换为真实可提供的信息。图表由真实接口或显式演示数据绘制，不沿用静态 SVG 曲线或固定悬浮提示。空值保留为“—”，历史缺失与零步保持区分。
