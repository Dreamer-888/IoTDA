## 接口契约与文档的差异

这些差异应与前端明确统一，并非都需要把代码改回旧文档。

| 项目 | 概要设计 | 当前接口 |
| --- | --- | --- |
| 登录凭据 | `UserLoginVO` 包含 `id/token`，术语表提到 JWT | HttpOnly Cookie；登录 `data` 为 `{user, authenticated: true}`，没有 token |
| 响应包装 | `{code, msg, data}`，`code` 为 1/0 | `{code, message, data}`，`code` 与 HTTP 状态一致，例如 200/401 |
| 设备状态 | `DeviceVO.online_status`，数值 1/0/-1 | 设备列表没有该字段；独立状态接口及报文快照使用字符串 `online/offline/unknown` |
| 统计结构 | `accel_x_max` 等平铺字段 | `metrics.accel_x.max/min/avg/range` 等嵌套结构 |
| 分页 | 定义 `PageResult(total, records)` | 设备列表为数组，历史步数按日期范围返回；当前没有分页响应。文档没有明确哪些业务接口必须分页，需要与验收约定同步。 |
| 步数历史和保存时间 | 初版只有两张表，没有明确该后续方案 | 已增加 `daily_steps`；用户后续确定北京时间 22:00 保存 |

当前前端应以 [接口交接说明](前端接口交接.md) 和 [OpenAPI](openapi.json) 为实际联调契约。

## 达到文档功能覆盖仍需完成的工作

1. **命令控制链路**：设置采样间隔、校准、设置久坐阈值；校验归属与参数，调用云端命令接口，关联命令结果、失败和超时。仅云端接受请求不能作为设备执行成功；采样间隔应在确认成功后更新。云端 service ID、命令名和参数需与产品模型及设备实现一致。
2. **WebSocket 后续验收**：已完成实现与本机握手/消息测试，继续使用真实设备验证持续上报、网络中断与重新连接。
3. **当前步数与目标约定**：提供当天当前累计查询，并确定目标由后端还是前端管理；后端管理时补充目标保存和查询。
4. **告警后续验收**：已采用用户确定的上升沿触发规则，继续确认设备实际复位行为；确认、关闭等工作流只有明确需要时再增加。
5. **同步设计与接口契约**：更新登录、响应包装、状态、统计结构和历史步数说明。云端主动属性查询、设备状态事件及数据库运维条目是否列入本实践项目的验收，也应在设计中明确。
