# 前端接口交接说明

核对日期：2026-10-15。本文对应当前代码中已注册的 **17 个 HTTP 业务接口和 1 个 WebSocket 接口**；实时协议详见 [WebSocket与告警](WebSocket与告警.md)。所有 URL 都相对于后端地址；OpenAPI 文件见 [openapi.json](openapi.json)。JSON 示例用于说明结构，示例中的用户和本地设备 ID 不代表当前数据库的真实分配。

## 1. 交接给前端负责人的材料

| 材料 | 内容 |
| --- | --- |
| 本文 | 接口用途、请求参数、响应字段、鉴权、数据单位和联调顺序 |
| [openapi.json](openapi.json) | OpenAPI 3.0.3 接口定义，可导入支持 OpenAPI 的接口管理工具 |
| 联调地址 | 后端负责人提供前端电脑能访问的实际地址，如 `http://后端电脑的局域网IP:5000` |
| 测试账号 | 约定一个测试账号；登录凭据单独交接，不写入公共接口文件 |
| 测试设备 | 对应账号获准绑定的云设备 ID、产品 ID；本地数字设备 ID 从设备列表取得 |
| 调试入口 | 构建前端后通过后端地址下的 `/test-ui/` 访问，包含登录、设备管理、实时监测和历史步数；WSL 统一启动见 [项目说明](../README.md) |

前端只调用后端 HTTP 接口。华为云 AMQP 凭据、MySQL 凭据和 `.env` 属于后端运行配置，不作为前端交接材料。

## 2. 接口总览

除注册、登录、退出外，以下接口都需要已登录 Cookie。退出接口即使尚未登录也返回成功。

| 方法 | 路径 | 用途 | 成功时的 `data` |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | 注册账号 | 用户对象；HTTP 201 |
| POST | `/api/auth/login` | 登录并设置 Cookie | `{user, authenticated: true}` |
| GET | `/api/auth/me` | 恢复或检查当前登录状态 | 用户对象 |
| POST | `/api/auth/logout` | 退出并清除当前会话 | `null` |
| GET | `/api/users/{user_id}` | 查询自己的资料 | 用户对象 |
| PATCH | `/api/users/{user_id}` | 修改自己的资料或密码 | 结果说明字符串 |
| GET | `/api/devices` | 查询自己绑定的设备 | 设备对象数组 |
| POST | `/api/devices` | 绑定获准使用的云设备 | 设备对象；HTTP 201 |
| PATCH | `/api/devices/{device_id}` | 修改设备名称 | 结果说明字符串 |
| DELETE | `/api/devices/{device_id}` | 解绑设备 | 结果说明字符串 |
| GET | `/api/telemetry/reports` | 获取自己的所有设备及最近报文 | 按设备分组的对象 |
| GET | `/api/devices/{device_id}/telemetry/latest` | 最新六轴数据与姿态，供仪表盘和模型使用 | 样本对象或 `null` |
| GET | `/api/devices/{device_id}/telemetry/window` | 最近短窗口曲线、回放 | `{device_id, seconds, count, filter, filter_window, samples}` |
| GET | `/api/devices/{device_id}/telemetry/summary` | 六个原始轴的窗口统计 | `{device_id, seconds, basis, count, metrics}` |
| GET | `/api/devices/{device_id}/telemetry/status` | 最近上报推断的设备状态 | 状态对象 |
| GET | `/api/telemetry/steps/daily` | 该用户的每日历史步数 | 日期范围与 `points` 数组 |
| GET | `/api/telemetry/alerts` | 当前用户已绑定设备最近七天的告警，按游标补取 | `{user_id,store_id,events,cursor,has_more,retention_seconds}` |

WebSocket `/api/telemetry/live` 的鉴权、订阅、快照、样本、状态和告警消息详见 [实时协议](WebSocket与告警.md)。

`user_id` 是应用用户的数字 ID；`device_id` 是 `GET /api/devices` 中的数字 `id`。华为云报文中的字符串 `device_id` 对应这里的 `cloud_device_id`，不要将它填入上述数字设备路径。

## 3. 请求、响应与登录

有请求体时使用 JSON 对象和 `Content-Type: application/json`，请求体上限 16 KiB。

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {}
}
```

HTTP 状态与 `code` 一致。注册和绑定设备成功为 201，其余成功业务请求为 200。读取业务数据使用 `result.data`；登录用户对象位于 `result.data.user`。

错误示例：

```json
{
  "code": 401,
  "message": "尚未登录",
  "data": null
}
```

所有响应带 `X-Request-ID`，反馈问题时交接请求路径、状态码和这个编号。不要依靠中文 `message` 判断接口类别。

| HTTP 状态 | 前端处理 |
| --- | --- |
| 400 | 显示字段或查询参数错误 |
| 401 | 保护接口会话失效时停止轮询、清空旧用户数据并回到登录流程；登录/改密码请求本身也可能因密码错误返回 401 |
| 403 | 显示访问权限不足，或设备未分配给当前用户 |
| 404 | 接口不存在，或指定设备不存在/不属于当前用户 |
| 409 | 用户名、邮箱、设备绑定冲突，或并发密码修改冲突 |
| 405 / 413 / 415 | 检查请求方法、请求体大小或媒体类型；当前无效 JSON 通常返回 400 |
| 500 | 后端内部错误，附带请求 ID 反馈 |
| 503 | 数据库繁忙或不可用；读取操作可以延迟重试，写入操作先查结果再决定是否重试 |

后端使用 HttpOnly 签名会话 Cookie，登录响应没有 token 字段。浏览器负责保存 Cookie；前端请求统一设置 `credentials: 'include'`。直接跨来源调用时，此配置影响 Cookie 的发送和登录响应 Cookie 的接收，参见 [MDN credentials](https://developer.mozilla.org/en-US/docs/Web/API/Request/credentials)。

页面首次加载先请求 `/api/auth/me`。未登录时只显示登录页面，不启动受保护的数据轮询。登录成功后读取设备列表，再启动当前用户的数据刷新。退出、切换账号或会话失效时，取消旧请求并清空图表、模型和设备状态，避免旧响应覆盖新账号页面。

## 4. 用户接口

注册：

```http
POST /api/auth/register
Content-Type: application/json
```

```json
{"username":"frontend_demo","password":"your-test-password","email":null}
```

用户名去除首尾空白后长度为 1–64，注册密码长度为 8–128。邮箱可省略或传 `null`；非空值最长 254 字符，后端验证格式并转为小写。注册成功不会自动登录。

登录：

```json
{"username":"frontend_demo","password":"your-test-password"}
```

登录密码接受 1–128 字符。账号不存在或密码错误均为 401。成功响应的 `data`：

```json
{
  "user": {
    "id": 1,
    "username": "frontend_demo",
    "email": null,
    "created_at": "2026-10-13T02:00:00+00:00",
    "updated_at": "2026-10-13T02:00:00+00:00"
  },
  "authenticated": true
}
```

`GET /api/auth/me` 和 `GET /api/users/{user_id}` 的 `data` 直接是上面的用户对象，不再嵌套 `user`。用户资料时间为 UTC ISO 字符串。用户接口仅允许操作自己，用户名 `root` 没有额外的应用管理权限。

修改资料：

```json
{"username":"new_name","email":"new@example.com"}
```

修改密码：

```json
{"current_password":"your-test-password","password":"your-new-test-password"}
```

以上请求发送到 `PATCH /api/users/{user_id}`。至少提供一个有效修改字段；邮箱字段省略表示不改，传 `null` 或空字符串表示清空。修改响应的 `data` 是说明字符串，修改资料后重新读取 `/api/auth/me`。修改密码成功会清除当前会话并使其他旧会话失效，需要重新登录。

## 5. 设备接口

绑定请求：

```json
{
  "cloud_device_id": "由后端负责人提供的云设备ID",
  "cloud_product_id": "由后端负责人提供的产品ID",
  "display_name": "我的六轴传感器",
  "hardware_model": null
}
```

设备和产品 ID 最长 128 字符，显示名称最长 100 字符且不能为空；硬件型号可省略或为 `null`，非空时最长 100。绑定需要后端预分配给登录账号，未分配/产品不匹配返回 403，已有绑定返回 409。归属取自登录 Cookie，提交 `user_id` 不会改变归属。

设备对象：

```json
{
  "id": 7,
  "user_id": 1,
  "cloud_device_id": "cloud-device-demo",
  "cloud_product_id": "product-demo",
  "display_name": "我的六轴传感器",
  "hardware_model": null,
  "sample_interval_ms": null,
  "last_seen_at": null,
  "created_at": "2026-10-13T02:00:00+00:00",
  "updated_at": "2026-10-13T02:00:00+00:00"
}
```

设备列表 `data` 是对象数组，无设备时为 `[]`。`sample_interval_ms` 是已有元数据字段，当前没有 HTTP 调整采样间隔接口。

改名请求体为 `{"display_name":"新名称"}`。解绑使用 DELETE，无需请求体；成功后重新获取设备列表并移除对应实时图表和模型。解绑清理实时缓冲，但保留已经累计的历史步数。

## 6. 实时样本与短窗口

`latest` 和 `window.samples[]` 中的样本结构一致。以下例子采用真实设备上报的属性值，时间与本地设备 ID 仅用于说明：

```json
{
  "device_id": 7,
  "reported_at": "2026-10-12T03:40:18+00:00",
  "cloud_event_at": "2026-10-12T03:40:18.976000+00:00",
  "received_at": "2026-10-12T03:40:19+00:00",
  "accel_x": -0.18,
  "accel_y": 8.65,
  "accel_z": 4.48,
  "gyro_x": 0.0,
  "gyro_y": 0.0,
  "gyro_z": 0.0,
  "roll": 62.73,
  "pitch": 1.08,
  "yaw": -48.14,
  "step_increment": 0,
  "is_sedentary": 0,
  "is_fall": 0,
  "accel_magnitude": 9.742961562071361,
  "gyro_magnitude": 0.0
}
```

| 字段 | 含义与单位 |
| --- | --- |
| `accel_x/y/z`、`accel_magnitude` | 三轴加速度与合加速度，m/s²；是否去除重力仍需设备端确认 |
| `gyro_x/y/z`、`gyro_magnitude` | 三轴角速度与合角速度，°/s |
| `roll/pitch/yaw` | 设备给出的姿态角，°；模型轴映射和旋转顺序仍待确认 |
| `step_increment` | 该条上报的步数增量，非负整数；不是当天总步数 |
| `is_sedentary/is_fall` | 设备给出的整数 0/1 标记 |
| `reported_at` | 设备服务上报时间 |
| `cloud_event_at` | 云通知事件时间 |
| `received_at` | 后端接收时间 |

时间字段都输出带时区的 UTC ISO 字符串，界面按北京时间格式化。合加速度、合角速度在数值溢出时可能为 `null`。没有样本时 `latest.data` 为 `null`，前端应显示“暂无数据”。

短窗口示例：

```http
GET /api/devices/7/telemetry/window?seconds=60&filter=none
GET /api/devices/7/telemetry/window?seconds=60&filter=moving_average&filter_window=5
```

`seconds` 默认 60，当前配置允许 1–300；上限随后端保留时间配置变化。`filter` 为 `none` 或 `moving_average`，`filter_window` 为 1–50、默认 5。查询参数不得重复。`data` 中的 `samples` 是按后端接收顺序返回的样本数组，`count` 为数组长度；无数据时为 `[]`。未开启滤波时响应 `filter_window` 为 `null`。

滑动平均只作用于六个原始轴，姿态角、步数和标记保持原值。窗口按后端接收时间选取，默认只保留五分钟；后端重启后六轴缓存清空。目前不能用此接口查询一个月的六轴历史。

统计接口接收 `seconds`，返回 `basis: "raw"`、`count` 和 `metrics`。`metrics` 包含六个原始轴，各轴都有 `min/max/avg/range`；`range` 是最大值减最小值。无样本时 `count: 0`，所有指标为 `null`。

状态接口的 `data` 包含 `device_id`、`status`、`basis`、`online_timeout_seconds`、`seconds_since_report`、`last_received_at`、`last_seen_at`。`status` 为 `online/offline/unknown`，依据近期后端上报推断，`basis` 固定为 `recent_reports`；当前在线阈值 30 秒。重启或五分钟缓存过期后可能变为 `unknown`，此字段不是华为云的权威在线状态。

## 7. 所有设备的报文查询

`GET /api/telemetry/reports` 返回：

```json
{
  "user_id": 1,
  "devices": [
    {
      "device_id": 7,
      "cloud_device_id": "cloud-device-demo",
      "display_name": "我的六轴传感器",
      "status": "unknown",
      "latest": null,
      "reports": []
    }
  ],
  "max_reports_per_device": 50,
  "retention_seconds": 300
}
```

每个 `reports[]` 元素包含 `sequence`、`device_id`、`received_at`、`raw`、`truncated`。`raw` 是格式化后的 JSON **字符串**，最长 16 KiB，截断时仅作文本展示，不保证还能解析为完整 JSON。序号仅在当前进程内有意义，重启可能从头开始。

报文接口响应含最近报文列表的快照，并非只含新增报文。使用 `device_id` 为设备卡片的键，在设备内按序号更新，避免重复追加。渲染文本可使用 `textContent`。退出或切换用户时清空旧数据；若返回的 `data.user_id` 与当前页面账号不一致，也应清空并重新确认登录状态。旧报文轮询实现保留在 [reports.js](../frontend/reports.js)；当前前端优先使用 WebSocket，连接失败后才在每次请求完成一秒后轮询所选设备的 latest/window/summary/status，见 [app.js](../frontend/app.js) 和 [api.js](../frontend/lib/api.js)。

## 8. 每日历史步数折线图

```http
GET /api/telemetry/steps/daily?start_date=2026-10-11&end_date=2026-10-13
```

该接口统计**当前用户所有设备合计的每日步数**，不是某一台设备的历史。无需传 `user_id`；额外传入其他用户 ID 也不会改变查询归属。

```json
{
  "user_id": 1,
  "timezone": "Asia/Shanghai",
  "start_date": "2026-10-11",
  "end_date": "2026-10-13",
  "points": [
    {"date": "2026-10-11", "steps": 3200, "has_data": true},
    {"date": "2026-10-12", "steps": 0, "has_data": true},
    {"date": "2026-10-13", "steps": null, "has_data": false}
  ]
}
```

起止日期均包含在内，格式为 `YYYY-MM-DD`，支持 1000–9999 年，最多 366 天，开始日期不能晚于结束日期。参数省略时默认查询包括今天的近 30 天；若只传结束日期，开始日期默认为此前第 29 天。

折线图横轴用 `point.date`，纵轴用 `point.steps`；`has_data: false` 表示未保存数据，应展示缺失，不要转为零。`has_data: true, steps: 0` 才是已记录零步数。数据按日期升序且补齐日期；有记录也不代表设备覆盖了全天。

MySQL 默认每天北京时间 **22:00** 保存当天截至该时刻的累计，22:00 后的增量继续累计，跨日后补齐到当天记录，迟到报文会补入原日期。因此当天在定时保存前通常为 `null`，该接口不能当作实时当天累计接口。只有后端更新后收到的有效报文才进入统计；当前没有自动补回旧数据的来源。前端在进入页面或改变日期范围时查询即可，无需每秒加载一个月历史。

## 9. 前端调用代码示例

以下示例假设前端通过同源 `/api` 代理访问后端：

```javascript
async function api(path, { method = 'GET', body, signal } = {}) {
  const response = await fetch(path, {
    method,
    credentials: 'include',
    cache: 'no-store',
    signal,
    ...(body === undefined ? {} : {
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(body),
    }),
  });
  const result = await response.json();
  if (!response.ok) {
    const error = new Error(result.message || `HTTP ${response.status}`);
    error.status = response.status;
    error.requestId = response.headers.get('X-Request-ID');
    throw error;
  }
  return result.data;
}

const login = await api('/api/auth/login', {
  method: 'POST',
  body: { username: 'frontend_demo', password: 'your-test-password' },
});
const currentUser = login.user;
const devices = await api('/api/devices');
if (devices.length > 0) {
  const localDeviceId = devices[0].id;
  const latest = await api(`/api/devices/${localDeviceId}/telemetry/latest`);
  // latest 可能为 null；模型使用 roll/pitch/yaw，按设备保存状态。
}
const daily = await api('/api/telemetry/steps/daily');
// daily.points 可直接作为每日步数图表数据。
```

实际页面为请求配置错误处理。读取轮询建议在上一请求结束后再安排下一次，避免重叠；用 AbortController 或请求代次标记丢弃切换用户/设备后的旧响应。3D 模型第一版可每秒获取最新姿态并作显示插值，实际动作信息量仍由设备上报频率决定。模型旋转前将 ° 转成弧度，并与设备负责人确认坐标和旋转顺序。

## 10. 联调地址与跨来源配置

后端本机默认地址为 `http://127.0.0.1:5000`；其他电脑的 `127.0.0.1` 指向其自身。需要局域网联调时，后端负责人启动：

```bash
.venv/bin/python run.py --host 0.0.0.0 --port 5000
```

将实际可访问的后端电脑 IP 和端口交给前端负责人，并确认双方网络及 Windows/WSL 的端口访问可用。`0.0.0.0` 是监听地址，不能作为前端的后端目标地址。

推荐前端使用同源代理。如果使用 Vite，可把下面配置合并到已有配置，并将 target 改成实际后端地址；参考 [Vite server.proxy](https://vite.dev/config/server-options.html#server-proxy)。

```javascript
import { defineConfig } from 'vite';

export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:5000', // 前后端不在同一电脑时改为后端实际地址
        changeOrigin: true,
      },
    },
  },
});
```

当前后端直接跨来源允许值为 `FRONTEND_ORIGIN=http://localhost:5173`，仅精确匹配一个来源；Cookie 当前为 `SameSite=Lax`、`Secure=false`。若直接访问后端而不经过代理，需要调整为实际前端来源，并让浏览器请求携带 Cookie。同源代理可减少不同主机之间的 Cookie 配置问题；CORS 放行并不能自动解除浏览器的跨站 Cookie 限制，参见 [MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)。

如果登录成功但后续接口持续 401，先查看请求有没有 Cookie，再检查地址是否混用了 localhost/127.0.0.1/局域网 IP、代理目标是否一致、后端签名密钥是否稳定，以及系统时间是否回拨。

## 11. 联调顺序与当前能力范围

1. 前端电脑打开后端 `/test-ui/`，确认能到达服务；确定代理目标与账号。
2. 登录，再请求 `/api/auth/me`，确认刷新页面后能恢复同一账号。
3. 查询设备列表；需要绑定时由后端先分配设备，再通过绑定接口创建记录。
4. 正常启动后端并让真实设备上报，检查 `latest`、`window` 和 `reports`；切换设备时各自保持独立数据。
5. 退出/切换账号，验证旧模型、曲线与待完成请求不会残留；访问别人的设备应为 404。
6. 接入每日步数查询，验证缺失日、零步数和日期范围；等待定时保存后确认当天记录更新。
7. 确认 XYZ 轴与旋转约定，分别绕三个轴旋转实物，校验模型方向。

已具备的后端能力是用户/设备管理、实时姿态、五分钟六轴窗口、每日步数历史、WebSocket 实时推送及告警补取。新增 `GET /api/telemetry/alerts` 和 WebSocket `/api/telemetry/live`，详见 [实时协议](WebSocket与告警.md)。云端控制命令和六轴长期历史接口仍未提供。旧 `POST /api/telemetry/report` 已移除；前端查询真实接收数据即可。`--peek-amqp` 仅终端预览，不更新页面缓存或步数累计，且同队列消费者可能分摊消息；正式联调使用正常 `run.py` 模式。
